# Cloudflare Pages Migration

This site can be deployed to Cloudflare Pages as a static site.

## Recommended Initial Setup

- Project source: `Jimonhitori/lol_predictor`
- Production branch: `codex/github-pages-static`
- Build command: leave empty
- Build output directory: `docs`
- Root directory: repository root

This keeps GitHub Pages and Cloudflare Pages using the same committed static files.

## Why No Build Command First

The current Pages version already commits generated files under `docs/`.
Starting with no Cloudflare build step avoids dependency, model, and data setup problems during the migration.

After the Cloudflare deployment is stable, a build command can be added later:

```bash
python -m lol_predictor.export_static --out-dir docs --max-details 80
```

That later step requires Python dependencies and data/model files to be available in the Cloudflare build environment.

## Runtime Behavior

- `index.html` is the main dashboard.
- `match.html?id=...` is the match detail page.
- `/match?id=...` is rewritten to `/match.html?id=...` by `_redirects`.
- Static JSON under `/static/data/` is cached for 60 seconds.
- HTML and app assets are revalidated so UI changes roll out quickly.

## Prediction JSON

Prematch predictions generated by `Jimonhitori/lol-pros-analyzer` can be fetched directly from its Pages site:

```text
https://jimonhitori.github.io/lol-pros-analyzer/pre_match_predictions.json
```

If the predictions should be served from this site later, copy or sync the file to:

```text
docs/pre_match_predictions.json
```

Then it will be available as:

```text
/pre_match_predictions.json
```

## Later Cloudflare-Specific Upgrade Path

1. Deploy the current `docs/` static site.
2. Add a small Worker or Pages Function for prediction/live-data proxying.
3. Move live data fetch/caching into Cloudflare Worker.
4. Use D1/KV only after the static site is stable.
